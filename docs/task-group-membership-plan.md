# پیش‌نمایش داخلی تغییر عضویت گروه

این مرحله فقط منطق خالص و آزمون است؛ هیچ API، رابط، تراکنش، migration یا تغییر دیتابیس ایجاد نمی‌کند. نباید از این خروجی به‌تنهایی مجوز نوشتن گرفت یا گروه آزمایشی با SQL دستی ساخت.

`planGroupMembershipChange` تنها از تصویر کامل و معتبرِ سمت سرور استفاده می‌کند؛ تصویر ارسالی مرورگر قابل اعتماد نیست. ورودی شامل گروه فعال و نسخه، همهٔ عضویت‌های جاری با شناسهٔ bigint به شکل رشته، نسخهٔ هر عضویت، وضعیت SyncEnabled، شناسهٔ کار مبنا، نسخهٔ مشاهده‌شده و عملیات صریح است.

- `set_sync`: فقط اعضای صریحاً انتخاب‌شده مستثنا یا دوباره فعال می‌شوند. این پیش‌نمایش انتخاب موقت دریافت‌کنندگان یک پیگیری را تغییر دائمی وضعیت همگام‌سازی تلقی نمی‌کند. بازفعال‌سازی هیچ سابقه‌ای را عقب‌گردی کپی نمی‌کند.
- `leave`: فقط خروج دائمی اعضای صریحاً انتخاب‌شده پیش‌نمایش می‌شود. اگر کمتر از دو عضو می‌ماند، بدون تصمیم جداگانه خروج مجاز اعلام نمی‌شود؛ گروه خودکار منحل نمی‌شود.
- `dissolve`: همهٔ اعضای جاری در پیش‌نمایش می‌آیند و تأیید صریح لازم است. خروج و انحلال هیچ سابقهٔ پیگیری را حذف نمی‌کنند.
- انتخاب تکراری، عضو خارج از گروه، نسخهٔ قدیمی، گروه غیرفعال، شناسهٔ دقیق‌نبودنی bigint و snapshot ناسازگار رد می‌شوند. نتیجه هیچ متن پیگیری یا جزئیات خصوصی را تکثیر نمی‌کند.

آداپتر نوشتن آینده باید زیر قفل زمان‌بندی و سپس قفل گروه، همهٔ اعضا و نسخه‌ها را روی یک اتصال تراکنشی دوباره بخواند؛ تصمیم مربوط به آخرین اعضا، receipt شناسهٔ عملیات، نسخهٔ گروه، حفظ تاریخچه و rollback را اتمیک و صریح اجرا کند. جابه‌جایی بین گروه‌ها نیازمند قفل گروه‌ها به ترتیب GroupID و تراکنش مستقل چندگروهی است؛ این مرحله انتقال یا افزودن عضو را پیاده نمی‌کند.

آزمون Node فقط منطق حافظه را با دادهٔ ساختگی بررسی می‌کند و آزمون SQL Server واقعی یا مجوز فعال‌سازی نیست.

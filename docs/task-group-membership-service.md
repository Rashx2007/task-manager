# سرویس داخلی تراکنشی تغییر عضویت

این مرحله فقط کتابخانهٔ داخلی و آزمون‌های شبیه‌سازی‌شده است؛ هیچ API یا رابطی اضافه نمی‌کند. آن را به مسیر عمومی متصل یا روی SQL Server واقعی فراخوانی نکنید. مدیریت افزودن و انتقال، باقی جریان‌های گروهی و آزمون هم‌زمانی روی SQL Server آزمایشی هنوز لازم‌اند. گروه آزمایشی را دستی با SQL نسازید.

`changeGroupMembership` در این مرحله فقط عملیات `set_sync` را دریافت می‌کند. ورودی شامل شناسهٔ گروه و کار مبنا، نسخهٔ مشاهده‌شدهٔ گروه، شناسهٔ یکتای درخواست و تصویر کامل نسخه‌دار اعضای مشاهده‌شده است؛ عضویت‌ها به‌شکل `{taskId, memberId, memberVersion, syncEnabled}` هستند و شناسهٔ bigint عضویت حتماً رشته است. `taskIds` باید صریح و `syncEnabled` حتماً boolean باشد. عملیات `leave` و `dissolve` پیش از تراکنش با خطای `EXIT_SCHEDULE_CHECK_REQUIRED` متوقف می‌شوند؛ تفکیک کارهای هم‌زمان می‌تواند تداخل زمان‌بندی ایجاد کند و ابتدا باید بررسی و راهکار آن اجرا شود.

روی یک اتصال و زیر قفل زمان‌بندی و قفل گروه، ابتدا رسید درخواست و سپس گروه و تمام عضویت‌های جاری خوانده می‌شوند؛ نسخهٔ گروه و تک‌تک شناسه‌ها، نسخه‌ها و وضعیت اعضا با تصویر مشاهده‌شده تطبیق می‌یابند. خروجی planner مجدداً بررسی می‌شود. عملیات تکراری با همان محتوا رسید را برمی‌گرداند؛ شناسهٔ تکراری با محتوای متفاوت رد می‌شود. هیچ عضو یا دریافت‌کننده‌ای خودکار انتخاب نمی‌شود.

در تغییر SyncEnabled هیچ تاریخچه‌ای کپی نمی‌شود؛ انتخاب دریافت‌کنندهٔ یک عملیات به‌خودی‌خود این وضعیت را تغییر نمی‌دهد. این سرویس هیچ ردیف Follow یا پیوندی حذف نمی‌کند و هیچ عضوی را خارج یا گروهی را منحل نمی‌کند. گروه و رسید در همان تراکنش با کنترل نسخه نوشته می‌شوند؛ در خطا rollback لازم است. تغییر بدون اثر SyncEnabled رسید دارد ولی نسخهٔ گروه را بی‌دلیل تغییر نمی‌دهد.

آزمون‌های Node فقط اتصال SQL و تراکنش شبیه‌سازی‌شده را بررسی می‌کنند. این آزمون‌ها صحت اجرای SQL Server واقعی، قفل‌های هم‌زمان یا رفتار در محیط کاربر را اثبات نمی‌کنند.

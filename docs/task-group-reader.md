# دریافت فقط‌خواندنی گروه کار — مرحلهٔ اتصال داده

## وضعیت

این مرحله چهار فایل جدید اضافه می‌کند. مسیر جدید فقط GET دارد؛ ایجاد گروه، افزودن/حذف عضو، تغییر زمان، ثبت پیگیری یا حذف اطلاعات را فعال نمی‌کند. رابط کاربری فعلی نیز هنوز این مسیر را فراخوانی نمی‌کند. اجرای migration جدید لازم نیست.

## درخواست

`GET /api/task-groups?taskId=<existing-task-id>`

پاسخ موفق:

```json
{
  "success": true,
  "data": {
    "taskId": 101,
    "group": null,
    "members": [],
    "warnings": []
  }
}
```

این نمونه برای کار موجودِ بدون گروه است. شناسهٔ 101 صرفاً نمونه است و نباید برای سیستم کاربر فرض شود. گروه‌های فعلی پس از نصب اولیه خالی‌اند؛ برای آزمودن این مسیر گروه دستی ایجاد نکنید.

در صورت وجود گروه، `group` شامل هویت و نسخهٔ آن و `members` شامل اعضای جاری، نسخهٔ عضویت، مشخصات دستگاه و اطلاعات زمان ثبت‌شده است. `IsOriginTask` عضو متعلق به کار درخواست‌شده را مشخص می‌کند. اعضای `SyncEnabled=0` نیز نمایش داده می‌شوند؛ استثنای انتشار پیگیری با خروج از گروه یکی نیست.

## ایمنی و محدودیت‌ها

- همهٔ دستورات SQL این مسیر SELECT و پارامتری هستند؛ عملیات نصب، نوشتن یا حذف اجرا نمی‌شود.
- آمادگی migration و قیدهای ایمنی پیش از خواندن داده کنترل می‌شود.
- نسخهٔ گروه قبل و بعد از دریافت اعضا مقایسه و عضویت کار مبنا دوباره کنترل می‌شود؛ تغییر مشاهده‌شده با 409 رد می‌شود.
- این روش خوش‌بینانه، جای قفل و کنترل دوباره در عملیات ذخیره را نمی‌گیرد. تمام نویسندگان آینده باید تغییر عضویت/پیگیری/زمان مشترک را تراکنشی انجام دهند و نسخهٔ گروه را به‌روز کنند. SQL دستی یا مسیر نویسندهٔ خارج از این قرارداد قابل پوشش نیست.
- پاسخ بدون گروه، مجوز ذخیرهٔ مستقل در آینده نیست؛ هر مسیر نوشتن باید عضویت لحظهٔ ذخیره را دوباره بررسی کند.
- پاسخ Cache-Control: no-store دارد و route به‌صورت dynamic است.
- کد نامعتبر 400، کار ناموجود 404، تعارض داده/نسخه 409، زیرساخت آماده‌نشده 503 و خطای غیرمنتظره 500 می‌دهد. جزئیات خصوصی خطای SQL ارسال نمی‌شود.
- در صورت چند دستگاه متفاوت برای یک کار یا چند ردیف زمان، مقدار دلخواه انتخاب نمی‌شود. وضعیت با AMBIGUOUS_ASSET یا MULTIPLE_SCHEDULE_ROWS در warnings گزارش می‌شود و فیلدهای مبهم دستگاه/زمان از SQL به‌صورت null برمی‌گردند. این داده‌ها نباید بدون رفع ابهام، مبنای ذخیرهٔ خودکار شوند.
- زمان‌های DueDateTime و EndDateTime همان قرارداد ساعت دیواری سرور را دارند؛ کلاینت باید از helper دیواری استفاده کند. CreatedAt و ModifiedAt گروه زمان واقعی UTC رویداد سیستمی‌اند و نباید با ساعت دیواری قرار کار اشتباه شوند.

## آزمون شبیه‌سازی‌شده

از ریشهٔ پروژه:

```powershell
node --experimental-vm-modules --test tests/task-group-reader.test.mjs
```

انتظار: 12 آزمون موفق و صفر شکست. آزمون‌ها پیاده‌سازی فعلی کتابخانهٔ زیرساخت را با DB و پاسخ HTTP شبیه‌سازی‌شده بارگذاری می‌کنند؛ اتصال واقعی به SQL Server ندارند. ExperimentalWarning مربوط به VM آزمایشی Node است.

## آزمون واقعی فقط‌خواندنی

برنامه را مثل همیشه اجرا نگه دارید. در PowerShell جداگانه، کد یک کار موجود را از ستون «کد کار» جدول اصلی وارد کنید:

```powershell
$taskId = Read-Host "کد یک کار موجود را وارد کنید"
$encodedId = [uri]::EscapeDataString($taskId.Trim())
Invoke-RestMethod -Method Get -Uri "http://localhost:3000/api/task-groups?taskId=$encodedId" -ErrorAction Stop | ConvertTo-Json -Depth 8
```

در صورت نبود گروه، success باید true، group برابر null و members خالی باشد. برای کد حذف‌شده 404 طبیعی است؛ کد کار موجود دیگری انتخاب شود. اگر سرور روی پورت دیگری اجراست، آدرس واقعی همان برنامه به‌کار رود.

این آزمون فقط اتصال خواندن و آمادگی زیرساخت واقعی را بررسی می‌کند. آزمون گروه دارای عضو، تعارض چند اتصال و مسیرهای نوشتن هنوز جداگانه لازم‌اند؛ جدول‌ها را برای آزمایش دستی پر نکنید.

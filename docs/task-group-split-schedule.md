# پیش‌نمایش زمان‌بندی پس از جداسازی اعضای گروه

این ماژول فقط محاسبهٔ خالص است. هیچ API، عملیات خروج/انحلال، تغییر زمان، SQL یا migration ایجاد نمی‌کند. نباید آن را با snapshot مرورگر یا خروجی این پیش‌نمایش به‌تنهایی برای نوشتن استفاده کرد.

`planGroupSplitSchedule` تصویر کامل و معتبر همهٔ کارهای قابل زمان‌بندی، گروه‌ها و عضویت‌های جاری را از آداپتر قابل‌اعتماد سمت سرور می‌گیرد، نه از مرورگر. تنظیم ساعات کاری و زمان شروع صریح و یکسان در هر دو محاسبه الزامی است. خروج و انحلال با فهرست صریح اعضا و نسخهٔ گروه شبیه‌سازی می‌شوند؛ برای انحلال همهٔ اعضای جاری باید انتخاب شوند. اگر در خروج کمتر از دو عضو می‌ماند، تصمیم مستقل دربارهٔ گروه لازم است.

- زمان‌بند گروهی ابتدا وضعیت فعلی و سپس عضویت فرضی پس از جداسازی را در حافظه بررسی می‌کند. تداخل زمان ثابت موجود یا ناشی از جداسازی جداگانه گزارش و پیش‌نمایش متوقف می‌شود.
- برای کارهای ثابتِ فعال که واقعاً از گروه خارج می‌شوند، می‌توان بازهٔ جایگزین صریح با همان مدت فرستاد؛ هیچ زمان ثابتی خودکار جابه‌جا نمی‌شود. تداخل این بازه با سایر واحدهای ثابت نیز بررسی می‌شود.
- همهٔ تغییرات زمان پیشنهادی، از جمله تغییرات کارهای دیگر ناشی از بازچینی کارهای غیرثابت، در نتیجه فهرست می‌شوند و به تأیید صریح نیاز دارند. این خروجی به‌خودی‌خود باعث ذخیره یا بازچینی نمی‌شود.
- خروج، انحلال و بازپیوستن سابقهٔ پیگیری را کپی یا حذف نمی‌کنند. اعضای تکمیل‌شده در زمان‌بندی فعال شرکت نمی‌کنند.

پیش از استفادهٔ واقعی، آداپتر باید کامل‌بودن مجموعه، داده‌های زمان کار/TimeDate و تنظیمات ساعات کاری را تحت قفل زمان‌بندی و قفل‌های لازم تضمین کند. همهٔ زمان‌ها، عضویت‌ها، نسخه‌ها، داده‌های مؤثر و تأیید کاربر باید در همان تراکنش دوباره بررسی شوند؛ تغییرات عضویت، بازچینی احتمالی، نسخهٔ گروه‌ها، رسید idempotency و rollback باید اتمیک باشند. پیش‌نمایش ناقص یا دادهٔ خارج از قفل مجوز نوشتن نیست. قفل و SQL باید جداگانه روی SQL Server آزمایشی بررسی شوند.

آزمون‌ها فقط الگوریتم حافظه و دادهٔ ساختگی را بررسی می‌کنند؛ هیچ SQL Server واقعی یا رابط برنامه آزمون نمی‌شود.

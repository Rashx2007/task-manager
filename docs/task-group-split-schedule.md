# پیش‌نمایش زمان‌بندی پس از جداسازی اعضای گروه

این ماژول فقط محاسبهٔ خالص است. هیچ API، عملیات خروج/انحلال، تغییر زمان، SQL یا migration ایجاد نمی‌کند. نباید آن را با snapshot مرورگر یا خروجی این پیش‌نمایش به‌تنهایی برای نوشتن استفاده کرد.

`planGroupSplitSchedule` تصویر کامل و معتبر همهٔ کارهای قابل زمان‌بندی، گروه‌ها و عضویت‌های جاری را از آداپتر قابل‌اعتماد سمت سرور می‌گیرد، نه از مرورگر. تنظیم ساعات کاری و زمان شروع صریح و یکسان در هر دو محاسبه الزامی است. خروج و انحلال با فهرست صریح اعضا و نسخهٔ گروه شبیه‌سازی می‌شوند؛ برای انحلال همهٔ اعضای جاری باید انتخاب شوند. اگر در خروج کمتر از دو عضو می‌ماند، تصمیم مستقل دربارهٔ گروه لازم است.

- زمان‌بند گروهی ابتدا وضعیت فعلی و سپس عضویت فرضی پس از جداسازی را در حافظه بررسی می‌کند. تداخل زمان ثابت موجود یا ناشی از جداسازی جداگانه گزارش و پیش‌نمایش متوقف می‌شود.
- برای کارهای ثابتِ فعال که واقعاً از گروه خارج می‌شوند، می‌توان بازهٔ جایگزین صریح با همان مدت فرستاد؛ هیچ زمان ثابتی خودکار جابه‌جا نمی‌شود. تداخل این بازه با سایر واحدهای ثابت نیز بررسی می‌شود.
- همهٔ تغییرات زمان پیشنهادی، از جمله تغییرات کارهای دیگر ناشی از بازچینی کارهای غیرثابت، در نتیجه فهرست می‌شوند و به تأیید صریح نیاز دارند. این خروجی به‌خودی‌خود باعث ذخیره یا بازچینی نمی‌شود.
- خروج، انحلال و بازپیوستن سابقهٔ پیگیری را کپی یا حذف نمی‌کنند. اعضای تکمیل‌شده در زمان‌بندی فعال شرکت نمی‌کنند.

پیش از استفادهٔ واقعی، آداپتر باید کامل‌بودن مجموعه، داده‌های زمان کار/TimeDate و تنظیمات ساعات کاری را تحت قفل زمان‌بندی و قفل‌های لازم تضمین کند. همهٔ زمان‌ها، عضویت‌ها، نسخه‌ها، داده‌های مؤثر و تأیید کاربر باید در همان تراکنش دوباره بررسی شوند؛ تغییرات عضویت، بازچینی احتمالی، نسخهٔ گروه‌ها، رسید idempotency و rollback باید اتمیک باشند. پیش‌نمایش ناقص یا دادهٔ خارج از قفل مجوز نوشتن نیست. قفل و SQL باید جداگانه روی SQL Server آزمایشی بررسی شوند.

آزمون‌ها فقط الگوریتم حافظه و دادهٔ ساختگی را بررسی می‌کنند؛ هیچ SQL Server واقعی یا رابط برنامه آزمون نمی‌شود.

## آداپتر تشخیصی داخلی

`previewGroupSplitSchedule` در سرویس زمان‌بند، داده‌های کارها، عضویت‌ها و گروه‌ها را با مسیر موجود و قفل زمان‌بندی در یک تراکنش می‌خواند و از تنظیم ساعات کاری و زمان شروع سمت سرور استفاده می‌کند؛ دادهٔ زمان‌بندی ارسالی مرورگر مبنا نیست. هیچ نوشتنی انجام نمی‌شود. در صورت وجود ثانیه یا کسری از ثانیه در زمان یک کار غیرثابت، به‌جای نمایش مقدار گرد‌شده به عنوان مقدار ثبت‌شده، پیش‌نمایش با خطا متوقف می‌شود.

تنظیمات ساعات کاری و همهٔ نویسندگان دیگر الزاماً با همین قفل هماهنگ نیستند؛ علاوه بر آن، وضعیت پس از تراکنش ممکن است تغییر کند. بنابراین نتیجه فقط تشخیصی است، مجوز نوشتن یا تأیید کاربر نیست و به API متصل نشده است. برای عملیات واقعی، خواندن و اعتبارسنجی مجدد همهٔ داده‌های مؤثر، تأیید صریح، قفل‌های کافی و تغییرات اتمیک همچنان ضروری‌اند. آزمون‌ها از بدل SQL استفاده می‌کنند، نه SQL Server واقعی.

## مقایسهٔ تشخیصی پیش‌نمایش

برای پیش‌نمایش آماده، سرویس یک اثرانگشت SHA-256 از داده‌های مؤثر سمت سرور، زمان آغاز و ساعات کاری، نسخهٔ گروه‌ها و شناسه/نسخهٔ اعضای جاری، ردیف‌های زمانی، انتخاب‌ها و تغییرات پیشنهادی می‌سازد. `revalidateGroupSplitPreview` همان محاسبه را در یک تراکنش خواندن جدید تکرار و با اثرانگشت قبلی مقایسه می‌کند. تغییر وضعیت یا اطلاعات یک کار دیگر، عضویت، تنظیمات یا زمان شروع می‌تواند مقایسه را ناموفق کند. پیش‌نمایش مسدود اثرانگشت ندارد.

این مقایسه صرفاً تشخیصی است: اثرانگشت امضا، احراز هویت، تأیید کاربر یا مجوز نوشتن نیست. نتیجه بلافاصله پس از پایان تراکنش می‌تواند قدیمی شود. اجرای واقعی همچنان باید محاسبه و مقایسه را زیر قفل‌های کافی در همان تراکنش نوشتن انجام دهد، تأیید صریح بگیرد و همهٔ تغییرات و رسید را اتمیک ثبت کند. تغییرات SQL مستقیم و مسیرهای دیگری که قفل مشترک را رعایت نمی‌کنند پوشش داده نمی‌شوند. API یا اجرای خروج/انحلال هنوز فعال نشده است.

## نمونهٔ داخلی جداسازی بدون تغییر برنامه

`splitGroupWithoutScheduleChanges` فقط برای حالتی نمونه‌سازی شده که بازبینی مجدد در همان تراکنش هیچ تغییر برنامه‌ای پیشنهاد نکند. تأیید صریح جداسازی، اثرانگشت پیش‌نمایش و شناسهٔ درخواست الزامی است؛ انحلال تأیید مستقل و انتخاب همهٔ اعضا را نیز لازم دارد. عملیات، عضویت‌های انتخاب‌شده را تاریخی می‌کند، نسخهٔ گروه را تغییر می‌دهد و رسید را در همان تراکنش ثبت می‌کند. سابقهٔ پیگیری و زمان‌ها را تغییر نمی‌دهد. بازپخش درخواست یکسان از رسید خوانده می‌شود. تداخل، تغییر داده‌ها، نیاز به تغییر زمان یا باقی‌ماندن کمتر از دو عضو در خروج، مانع عملیات است.

این نمونه **به هیچ API یا رابطی وصل نیست** و مسیر فعلی خروج/انحلال همچنان مسدود است. مستقیماً روی دادهٔ واقعی فراخوانی نشود: پیش از استفاده، قفل‌ها، rollback و رقابت تراکنش‌ها باید روی SQL Server آزمایشی مستقل بررسی شوند و مسیرهای نوشتن دیگر و بقیهٔ مدیریت گروه تکمیل شوند. پشتیبانی از تغییر برنامه و بازچینی اتمیک، انتقال، افزودن عضو و سایر قابلیت‌ها در این نمونه وجود ندارد. آزمون‌های فعلی تنها بدل SQL هستند.

## نمونهٔ داخلی جداسازی همراه بازچینی

`splitGroupWithScheduleChanges` یک نمونهٔ داخلیِ جداگانه برای خروج یا انحلالی است که پیش‌نمایش آن تغییر زمان دارد. تأیید صریح عضویت، تأیید صریح همهٔ تغییرات زمان، اثرانگشت و شناسهٔ درخواست الزامی‌اند؛ انحلال علاوه بر آن تأیید مستقل می‌خواهد. ابتدا پیش‌نمایش و اثرانگشت در همان تراکنش دوباره محاسبه می‌شوند. برای کارهای تغییرکننده، سازگاری اولویت، زمان، مدت و اجزای تاریخ/ساعت بین نسخهٔ کار و زمان‌بندی بررسی می‌شود؛ ناسازگاری یا مقدار ناقص مانع عملیات است.

در نمونه، فقط زمان‌های نمایش‌داده‌شده در پیش‌نمایش در Tsk و TimeDate به‌روزرسانی می‌شوند؛ وضعیت اتمام، Finish، اولویت، مدت و پیگیری دست نمی‌خورند. نسخهٔ گروه مبنا و دیگر گروه‌هایی که زمان اعضایشان تغییر می‌کند به‌روزرسانی و رسید در همان تراکنش ثبت می‌شود. بازهٔ جایگزین ثابت فقط با انتخاب صریح و بررسی تداخل قابل برنامه‌ریزی است. تکرار درخواست یکسان رسید را بازمی‌گرداند. اگر هیچ تغییر زمانی لازم نباشد، این مسیر آن را نمی‌پذیرد.

**محدودیت مهم:** این کد به مسیر عمومی یا رابط متصل نیست و نباید مستقیماً روی دادهٔ واقعی فراخوانی شود. عبارت‌های SQL، قالب پارامترها، قفل‌های واقعی، rollback، رقابت بین تراکنش‌ها و رفتار schema واقعی باید ابتدا روی یک SQL Server و پایگاه آزمایشی مستقل بررسی شوند. تست‌های فعلی فقط بدل SQL هستند. همهٔ نویسندگان بیرون از برنامه الزاماً قفل مشترک را رعایت نمی‌کنند؛ قابلیت نهایی هنوز آماده نیست.
